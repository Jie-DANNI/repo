# 忆循环 MemoLoop · 方案与架构

## 1. 产品故事（用于演示视频开场）

> 你上传了一份《机器学习》课件。三天后你以为自己还记得"偏差-方差权衡"，点开复习卡——这次不是让你看定义，AI 抛出一道情景题："你在调参时发现训练误差很低但验证误差很高，用偏差-方差的语言解释这个现象并给出应对策略。"你答漏了"增加数据量对高偏差无效"这一点。两天后，AI 在复习时**只针对这个漏洞**追问你。一周后，这张卡片的题型变成了费曼式讲解："假设向一个没学过统计的学弟，讲清楚为什么偏差和方差此消彼长。"
> ——复习不是重复看，而是递进地记住。这就是忆循环。

```
┌──────────────────────────────▼─────────────────────────────────────┐
│                        FastAPI (异步)                              │
│  ┌────────┐ ┌────────┐ ┌──────────┐ ┌─────────┐ ┌──────────────┐  │
│  │认证模块 │ │文档解析 │ │RAG检索    │ │FSRS调度  │ │三个AI Agent:  │  │
│  │JWT     │ │PDF→切块 │ │pgvector  │ │复习队列  │ │抽取/出题/追问 │  │

```

三个 AI Agent（技术文档"AI 技术方案"的核心）：

| Agent | 职责 | 输入 → 输出 |
|---|---|---|
| Extractor | 文档切块 → 结构化知识点卡片 | chunks → knowledge_points |
| Quizmaster | 按"复习轮次 × 记忆状态"生成升级题型 | 知识点+错因历史+round → quiz_item(JSON) |
| Socratic | 答题后评分 + 针对错因定向追问 | 答案+rubric → 反馈 + 追问会话 |

## 3. 创新点（写进技术文档，评委就看这三条）

1. **题型随记忆深度升级的复习机制**：第 1 轮识别（判断/填空）→ 第 2 轮理解（选择/简答）→ 第 3 轮应用（情景题）→ 第 4 轮起费曼式讲解。复习轮次由 FSRS 的 stability/difficulty 共同驱动，不是随机出题。对标产品（Anki、Quizlet）均为固定题型重复。
2. **错因驱动的定向追问**：每次作答由 Quizmaster 按统一评分量规（rubric）打分并输出结构化错因标签（error_tags），Socratic Agent 在后续复习中只围绕历史错因标签追问，形成"漏斗式补弱"。
3. **工程化的 RAG 混合检索**：向量检索 + BM25 关键词检索加权融合（RRF），切块按文档标题层级而非固定 token，并在技术文档中给出不同切块策略的检索质量对比实验——这就是评委要的"优化策略"实证。

## 4. 数据库概览（详见 db/schema.sql 与 02 文档）

- 内容层：documents → chunks(向量) → knowledge_points
- 调度层：review_records(FSRS状态) → review_logs(全量日志，用于统计页)
- 作答层：quiz_items → quiz_responses → conversations/messages(追问会话)
- 实证层：prompt_versions（记录每次 prompt 迭代，技术文档直接引用）

## 6. 风险与兜底

| 风险 | 兜底方案 |
|---|---|
| PDF 解析质量差 | 换用 pymupdf + 结构感知切块；演示时用排版干净的课件 |
| LLM 输出 JSON 不合法 | response_format=json_object + Pydantic 校验 + 重试≤2 次 + 降级为普通题干 |
| SSE 在 Nginx 后被缓冲 | Nginx 配置 `proxy_buffering off`，提前验证 |
| 复习场景演示周期长 | 出题时允许 review_round 手动推进（仅演示账号），视频里展示题型演变 |
