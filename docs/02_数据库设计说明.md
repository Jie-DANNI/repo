# 数据库设计说明（对照 db/schema.sql）

## 分层设计：四层流水线

```
内容层  documents ─→ chunks ─→ knowledge_points
                    (RAG素材)   (复习卡片)
调度层  review_records ─→ review_logs
        (FSRS记忆状态)    (全量行为日志)
作答层  quiz_items ─→ quiz_responses ─→ conversations ─→ messages
        (升级题型)     (评分+错因)      (定向追问会话)
实证层  prompt_versions / daily_stats
```

## 核心表速查

| 表 | 作用 | 关键字段 / 关键设计 |
|---|---|---|
| users | 账号，含 `role='demo'` 评审演示账号 | password_hash 用 bcrypt |
| learning_profiles | 用户长期画像 | `weaknesses` JSONB 数组：定向追问的宏观依据 |
| documents | 上传的资料 | `status` 状态机：uploaded→parsing→chunked→extracted→failed |
| chunks | 文档切块 + 向量 | `heading_path` 保留标题层级（结构感知切块）；hnsw + trgm 双索引支撑混合检索 |
| knowledge_points | 知识点卡片 | `(document_id, title)` 唯一约束防重复抽取；difficulty/importance 驱动出题 |
| review_records | **FSRS 调度核心** | stability/difficulty/retrievability/state/due_at；部分索引 `WHERE state<>'new'` 加速到期队列 |
| review_logs | 复习全量日志 | rating(1-4 FSRS 评级) + review_round + 新记忆状态快照，统计页与热力图数据源 |
| quiz_items | AI 生成的题目 | `quiz_type` 由 review_round 决定；`rubric` JSONB 是评分依据；`generation_meta` 记录模型/耗时/prompt版本 |
| quiz_responses | 作答记录 | **`error_tags` 是全项目最关键字段**——错因标签回流给出题与追问 Agent |
| conversations / messages | 苏格拉底追问会话 | `trigger_tags` 记录"这次追问在补哪个洞" |
| prompt_versions | Prompt 版本台账 | UNIQUE(scene, version)；技术文档"优化策略"章节直接截图此表 |
| daily_stats | 每日复习统计 | 复合主键(user_id, stat_date)，前端热力图零聚合成本 |

## 三条核心数据流（对着表讲）

**① 建卡流**：POST 上传 PDF → documents(parsing) → 解析切块 → chunks(embedding) → RAG 检索 + Extractor Agent → knowledge_points + review_records(state=new, due_at=now)

**② 复习流（每日主流程）**：
`review_records WHERE due_at <= now()` → 按 due_at 升序取 20 张 → 每张卡片：Quizmaster Agent 依据 `review_round + knowledge_points.difficulty + 历史 error_tags` 生成 quiz_item（SSE 流式下发）→ 用户作答 → rubric 评分 → 写 quiz_responses(error_tags) + review_logs(rating) → FSRS 更新 review_records(due_at)。

**③ 补弱流**：评分 < 0.8 或 error_tags 非空 → 创建 conversations(trigger_tags=error_tags) → Socratic Agent 多轮追问 → 会话结束把 error_tags 聚合进 learning_profiles.weaknesses → 下次出题时 Quizmaster 读 weaknesses 提高相关考点权重。

## review_round 与题型映射（创新点①的落地规则）

| round | quiz_type | 形态 | 评分方式 |
|---|---|---|---|
| 1 | recognition | 判断题 / 填空（挖关键词） | 客观比对 |
| 2 | choice | 四选一 + 简答 | 客观 + rubric |
| 3 | scenario | 情景应用题（结合 weaknesses 个性化） | rubric 加权 |
| 4+ | feynman | "讲给小白听"，AI 演演小白反问 | rubric + 追问深度 |

round 取自 review_records.reps（允许评委演示账号手动 +1 以便视频里展示题型演变）。

## 向量维度与索引

- `vector(1536)`：若你换 Embedding 模型（如 bge-m3 是 1024 维），只需 `ALTER TABLE ... ALTER COLUMN embedding TYPE vector(1024)`，两处同步改；
- 检索质量实验（技术文档用）：对同一文档分别用「固定512 token切块」vs「标题层级切块」各做 20 条查询，记录命中率差异，填进 prompt_versions.metrics 同款表格。
