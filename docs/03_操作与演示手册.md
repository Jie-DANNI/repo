## 第〇部分：每次开始前的准备（2 分钟）

### 0.1 启动三个服务

打开 **PowerShell**（普通权限即可），依次执行三条命令（**每条命令用一个单独的窗口**，执行后窗口别关）：

```powershell
# 窗口1：启动数据库（如果 Docker Desktop 没开，先打开它等鲸鱼图标变绿）
cd "F:\buddy create\memoloop"
& "C:\Program Files\Docker\Docker\resources\bin\docker.exe" compose up -d postgres

# 窗口2：启动后端
cd "F:\buddy create\memoloop\backend"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 窗口3：启动前端
cd "F:\buddy create\memoloop\frontend"
npm run dev
```

### 0.2 验证三个服务都活着

浏览器打开 `http://127.0.0.1:8000/api/health`，看到这样的 JSON 就说明全通了：

```json
{"status":"ok","db":true,"db_version":"PostgreSQL 16.15 ...","llm_configured":true,"llm_model":"deepseek-ai/DeepSeek-V4.1-Flash"}
```

三个字段分别确认：数据库连通、大模型已配置、用的什么模型。
再打开 `http://localhost:5173/login`，能出现登录界面即前端正常。

## 第二部分：Swagger 接口文档演示（核心，10-15 分钟）

这是目前**最有含金量**的演示方式——19 个接口可以交互式操作，每一步都能看到真实 AI 输出。

### 打开

浏览器访问 `http://127.0.0.1:8000/docs`

### 步骤 1：登录拿令牌（1 分钟）

1. 在接口列表里找到 **POST /api/auth/login**，点开它前面的黑色三角展开；
2. 点右侧 **「Try it out」** 按钮（此时请求体变成可编辑状态）；
3. 在 Request body 里确认内容如下（默认就是演示账号的话直接用）：

```json
{
  "email": "demo@memoloop.cn",
  "password": "Demo@2026"
}
```

4. 点蓝色 **「Execute」** 按钮；
5. 往下翻到 **Response body**，看到 `"access_token": "eyJhbGci..."` 一长串字符——**全选复制它**（注意别带上引号）。

**预期效果**：返回 200 + 一串 JWT 令牌 + 用户信息（`role: demo`）。
**讲解词**：「JWT 鉴权，7 天有效期，所有业务接口都要带令牌。」

### 步骤 2：全局授权（30 秒）

1. 页面拉到最顶上，点 **「Authorize」** 绿色按钮（一把锁的图标）；
2. 在 Value 输入框里**粘贴刚才复制的令牌**；
3. 点 **「Authorize」** → 点 **「Close」**。
   现在所有接口都自动带上你的身份了，后面不用再手动填。

### 步骤 3：查看知识库（1 分钟）

1. 找到 **GET /api/documents** → Try it out → Execute；
2. Response 里能看到文档列表，其中 `id=4` 的文档 `"status": "extracted"`（已建库）、`"chunk_count": 3`。
   **讲解词**：「上传的 PDF 被解析成 3 个语义切块，并完成了向量化。」

### 步骤 4：看 AI 抽出的知识点（1 分钟）

1. 找到 **GET /api/knowledge-points** → Try it out；
2. 在 `document_id` 参数填 `4`，`size` 填 `20` → Execute；
3. **预期效果**：返回 6 个知识点——梯度下降基本原理、批量梯度下降、随机梯度下降、小批量梯度下降、动量法、Nesterov动量，每个都带 `difficulty`（难度）、`importance`（重要性）、`keywords`。

**讲解词**：「Extractor Agent 从课件里抽出的知识点卡片，不是简单切块，是带难度/重要性/关键词的结构化知识单元——这是后续出题和调度的原子单位。」

### 步骤 5：今日复习队列（1 分钟）

1. 找到 **GET /api/review/today** → Try it out → `limit` 填 `10` → Execute；
2. **预期效果**：6 张到期卡片。注意两个细节：
   - `kp_id=1 梯度下降基本原理` 的 `round=2`、`quiz_type=choice`（因为它被答错过一次，升轮了）；
   - 其余 5 张 `round=1`、`quiz_type=recognition`（判断题）。

**讲解词**：「FSRS 遗忘曲线调度：每张卡有自己的记忆稳定度，到期才出现。复习轮次决定题型难度——这是创新点之一：**同一个知识点，每次复习题型都会升级**：判断→选择→情景→费曼讲解。」

### 步骤 6：AI 流式出题（⭐ 重头戏，2 分钟）

1. 找到 **POST /api/review/{kp_id}/quiz** → Try it out；
2. `kp_id` 填 `1`（这是 round=2 的卡，会出选择题）→ Execute；
3. **预期效果**：Server response 不是一次返回，而是**一段段追加的事件流**，你能看到：
   - `{"type": "meta", "round": 2, "quiz_type": "choice"}` —— 题型元信息；
   - `{"type": "chunk", "text": "…"}` —— **题目文本一个个字往外蹦**（SSE 流式，就像 ChatGPT 打字机效果）；
   - `{"type": "options", ...}` —— 四个选项 A/B/C/D；
   - `{"type": "done", "quiz_item_id": …}` —— 题目落库返回 ID。

**讲解词**：「Quizmaster Agent 出题：流式输出（SSE 而非 WebSocket 的选型理由：单向推送足够、自带断线语义、代理友好）；出题时注入了这张卡的历史错因——你可以再出一张 round=1 的题对比，难度明显不同。」

> 💡 可以再做一次：`kp_id` 填 `2`（round=1），对比看判断题长什么样。

### 步骤 7：作答 + AI 评分 + 错因标签（⭐ 重头戏，2 分钟）

1. 先看上一步 `done` 事件里的 `quiz_item_id`（**记下这个数字**，假设是 `3`）；
2. 找到 **POST /api/quiz/{quiz_item_id}/answer** → Try it out；
3. `quiz_item_id` 填刚才的 ID，请求体里 `answer_text` **故意填一个错误说法**，比如：

```json
{
  "answer_text": "梯度下降就是沿着正梯度方向更新参数，学习率越大收敛越快，没有上限。"
}
```

4. Execute 后看 Response，**预期效果**（重点讲这几块）：
   - `"score": 0` 左右 —— AI 按量规（rubric）逐点评分；
   - `"per_point": [...]` —— **每个评分点命中/未命中明细**（透明评分，不是黑箱给分）；
   - `"error_tags": ["概念混淆", ...]` —— 错因标签，来自固定词表；
   - `"fsrs": {"state": "Learning", "stability": ..., "due_at": ...}` —— **记忆状态被更新**：答错 → 稳定度低 → 明天还得来复习；
   - `"conversation_id": ...` —— 答差了自动创建了追问会话（**记下这个 ID**）。

**讲解词**：「评分 Agent 的输出三层：分数只是表象，per_point 是可解释的评分依据，error_tags 是结构化错因——它同时驱动两件事：FSRS 间隔调整 + 下轮出题避开已掌握、主攻弱项。这就是错因闭环，创新点之二。」

### 步骤 8：苏格拉底定向追问（⭐ 重头戏，2 分钟）

1. 找到 **POST /api/conversations/{conversation_id}/messages** → Try it out；
2. `conversation_id` 填步骤 7 返回的 ID（或直接用已有的 `1`）；
3. 请求体随便说一句错的/含糊的话：

```json
{
  "content": "我觉得沿哪个方向更新都行吧，反正多迭代几步就到了。"
}
```

4. Execute，**预期效果**：导师回复流式蹦出，并且**它不会直接纠正你**，而是反问引导。上次真实运行时它的回复是：

> 「设想你蒙眼下山：随便迈一步，和朝最陡的下坡方向迈，结果会一样吗？」

**讲解词**：「Socratic Agent 只围绕你被判定的错因追问，一次不超过 5 轮，引导学生自己想通——这对应教育学里的'生成效应'，比直接给答案记忆留存高 2-3 倍。」

5. （可选）多轮对话：对着同一个接口再发 2-3 条消息，看它怎么逐步收束并 `closed`。

### 步骤 9：学习画像闭环（1 分钟）

1. 找到 **GET /api/stats/overview** → Try it out → Execute；
2. **预期效果**：
   - `error_top`：你的错因排行榜（如 `[{"tag": "概念混淆", "count": 2}]`）；
   - `retention`：记忆保有率；
   - 复习热力图数据、知识点总数。

**讲解词**：「所有作答的错因聚合进学习画像——这份数据反过来影响下次出题的侧重点，形成完整闭环：**考→评→诊→治→再考**。」

## 第三部分：从零完整体验（拿自己的课件，10 分钟）

这一部分适合你想**彻底验证系统**或准备录视频时使用。

1. **注册自己的账号**：`POST /api/auth/register`（Try it out，填邮箱/昵称/密码，密码要字母+数字组合）→ 拿到自己的 token 重新 Authorize；
2. **准备一份 PDF 课件**：任何有「章/节标题 + 正文」结构的讲义都行（建议 5-20 页）；
3. **上传**：`POST /api/documents` → Try it out → 在 `file` 一栏选你的 PDF → Execute；
   - 返回 `id`，此时 status=`uploaded`，后台自动解析切块；
4. **等切块完成**：隔几秒调一次 `GET /api/documents/{id}/chunks`，`total > 0` 即完成（可看到每个切块的 `heading_path` 标题路径和 token 数）；
5. **触发 AI 建库**：`POST /api/documents/{id}/extract` → Execute（返回「构建任务已启动」）；
   - 然后轮询 `GET /api/documents`，等 status 从 `extracting` 变成 `extracted`（1-3 分钟，取决于文档大小，真实调用 embedding+LLM）；
   - 失败的话 `parse_error` 里有详细原因；
6. 之后重复第二部分的步骤 4-9（知识点 ID 换成你自己文档的）。

## 第四部分：故障排查速查表

| 症状 | 原因 | 解决 |
|---|---|---|
| `localhost:5173` 打不开 | 前端没启动 | 窗口3 重跑 `npm run dev` |
| `127.0.0.1:8000` 打不开 | 后端没启动 | 窗口2 重跑 uvicorn 命令 |
| `/api/health` 返回 `db:false` | 数据库容器没起 | 先开 Docker Desktop（等图标变绿）→ 跑窗口1 命令 |
| `llm_configured:false` | .env 没读到 | 确认 `F:\buddy create\memoloop\.env` 存在且 key 正确，重启后端 |
| 上传 500 / 报 `http protocol` | 老进程占 8000 端口 | PowerShell: `Get-NetTCPConnection -LocalPort 8000` 查 PID → `Stop-Process -Id <PID> -Force` → 重启 |
| extract 一直 `extracting` | 大文档+免费模型慢 | 等；>5 分钟查 `parse_error` |
| 端口被占用错误 | 5173/8000 被其他程序占 | 同上命令查杀，或换端口 |
| SSE 出题很慢 | 免费档限速 | 正常现象；录视频前充 10 元升级速度 |

## 附：录演示视频的叙事线（供 5-8 分钟视频参考）

1. **痛点**（30s）：期末复习=反复重读，效率低；现有工具只有卡片没有诊断。
2. **上传→建库**（1min）：拖入课件 → 切块 → 知识点卡片生成（讲 heading_path 智能切块）。
3. **复习流**（2min）：今日队列 → 判断题 → 故意答错 → 流式评分 + 错因标签出现。
4. **追问**（1.5min）：AI 导师反问「蒙眼下山」名场面 → 引导自己想通。
5. **闭环**（1min）：统计页错因 Top5 + 下一张同知识点题目变难/避开已掌握。
6. **技术亮点**（1min）：FSRS-4.5 vs SM-2、混合检索 RRF、三 Agent 分工、SSE 选型、prompt_versions 实证迭代。

> ⚠️ 录视频时：终端里别露出 API key；浏览器缩放调到 125% 保证评委能看清字。
