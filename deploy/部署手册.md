# MemoLoop · P10 生产部署手册

> 评审演示地址目标：公网可访问、评委打开即有数据、SSE 流式正常。
> 本地已完成全真彩排（生产镜像 + nginx + 完整建卡链路），服务器上只是重复同样的命令。

## 一、你需要做什么（只有 3 件事）

| # | 事项 | 说明 |
|---|------|------|
| 1 | **买一台云服务器** | 推荐 2核4G，见下表，约 30~90 元/月，比赛结束即退 |
| 2 | **配一次安全组 + 装 Docker** | 10 分钟照抄命令 |
| 3 | **把项目传上去跑一条命令** | `bash deploy/init.sh`，全自动 |

**服务器选购建议**（任选其一，轻量应用服务器即可）：

| 云商 | 规格 | 参考价 | 备注 |
|------|------|--------|------|
| 阿里云轻量 | 2核4G 60G SSD 4M 带宽 | ~60-90元/月 | 新用户活动价更低 |
| 腾讯云轻量 | 2核4G 60G SSD 4M 带宽 | ~50-80元/月 | 同上 |
| 系统 | **Ubuntu 22.04 / 24.04** | — | 手册命令按 Ubuntu 写 |

> 带宽 4M 起步：页面静态资源 ~200KB + SSE 文本流，够用。内存 4G 是底线（postgres + 2 个 uvicorn worker + nginx）。

## 二、服务器初始化（SSH 登录后逐条执行）

### 2.1 安全组 / 防火墙

云控制台 → 安全组，**只放行**：

| 端口 | 用途 |
|------|------|
| 22 | SSH（建议绑定你的 IP 或改为密钥登录） |
| 80 | HTTP —— 评审访问入口 |
| 443 | HTTPS（可选，见第五节） |

> 数据库 5432、后端 8000 **一律不对公网开放**，全部走容器内网。

### 2.2 安装 Docker

```bash
curl -fsSL https://get.docker.com | bash -s -- --mirror Aliyun
systemctl enable --now docker
docker compose version   # 确认 v2 插件可用
```

## 三、上传项目并一键部署

### 3.1 上传代码（本地 PowerShell/Git Bash 执行）

```bash
# 方式 A：压缩包上传（最简单，排除本地缓存）
cd "F:/buddy create"
tar --exclude='memoloop/frontend/node_modules' \
    --exclude='memoloop/backend/.venv' \
    --exclude='memoloop/backend/storage/[0-9]*' \
    --exclude='memoloop/output' \
    -czf memoloop-deploy.tar.gz memoloop
scp memoloop-deploy.tar.gz root@<服务器IP>:/opt/

# 服务器上解压
ssh root@<服务器IP>
cd /opt && tar xzf memoloop-deploy.tar.gz && mv memoloop memoloop_app 2>/dev/null || true
```

> `.env`（含硅基流动密钥）会随包上传；服务器只你一个人可登录，无泄漏面。
> 传输后可 `rm memoloop-deploy.tar.gz` 清理。

### 3.2 一键初始化（服务器上）

```bash
cd /opt/memoloop
bash deploy/init.sh
```

脚本自动完成：
1. 由 `.env` 生成 `.env.prod`（数据库指向容器内网、CORS 加公网 IP）
2. `docker compose -f docker-compose.prod.yml up -d --build`（前端首次构建 3~5 分钟）
3. 等待 `/api/health` 通过（含 postgres 连通检查）
4. 建演示账号 `demo@memoloop.cn / Demo@2026` + 导入预置课件并完成建卡（真实 LLM 调用，1~3 分钟）

完成后即得到：**http://服务器IP** 。

## 四、评审期自愈（强烈建议装上）

```bash
# 每分钟自检：curl /api/health 失败 → 自动重启 backend → 刷新 nginx DNS → 兜底全栈重启
echo '* * * * * root bash /opt/memoloop/deploy/selfcheck.sh >> /var/log/memoloop-selfcheck.log 2>&1' \
  > /etc/cron.d/memoloop-selfcheck
chmod 0644 /etc/cron.d/memoloop-selfcheck
```

日常运维：

```bash
docker compose -f docker-compose.prod.yml logs -f backend   # 看日志
docker compose -f docker-compose.prod.yml restart           # 重启全部
docker compose -f docker-compose.prod.yml down               # 停止（数据卷保留）
```

## 五、HTTPS（可选）：两种情况

**情况 A：没有域名（推荐，零成本零风险）**
直接用 `http://IP` 评审。赛项验收的是功能与 AI 设计，非 TLS。已在本地彩排验证过完整链路。

**情况 B：域名已完成 ICP 备案**
```bash
# DNS A 记录指到服务器 IP 后：
apt install -y certbot python3-certbot-nginx   # 若前端直接由宿主 nginx 承载可走这路
# 本项目前端在容器里，推荐改用 standalone 模式签发后挂载：
certbot certonly --standalone -d your.domain.com
# 然后在 docker-compose.prod.yml 的 frontend 服务 ports 加 "443:443"，
# nginx.conf 的 server 块加 listen 443 ssl 与证书路径（宿主 /etc/letsencrypt 挂载进容器），
# 再 docker compose -f docker-compose.prod.yml up -d 重建前端容器。
```

> 注意：国内服务器 + 未备案域名 = 80/443 端口会被云商拦截。备案需 1~3 周，赶不上 11/18 截止，**没备案就不要绑域名**。

## 七、故障速查

| 现象 | 排查 |
|------|------|
| 打不开页面 | 安全组 80 端口未放行 / `docker ps` 看 mloop-web 是否 Up |
| API 502 | `docker compose -f docker-compose.prod.yml logs backend`；多为 LLM 超时，等自愈脚本重启 |
| SSE 不流式/一次吐出 | 确认走的是 80 端口 nginx（不要直连 8000）；确认 mloop-web 容器用的是 `deploy/nginx.conf` 最新镜像 `--build` |
| 建卡一直 failed | `.env` 的 LLM_API_KEY 失效或欠费；`logs backend` 看 parse_error |
| 数据想清空重来 | `docker compose -f docker-compose.prod.yml down -v`（危险：删数据卷）后重跑 init.sh |
